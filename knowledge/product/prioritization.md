# Product prioritization (framework)

Use this structure when drafting or reviewing priorities. Fill in **Betterfly-specific** initiatives in separate files as needed.

## Dimensions

1. **User impact** — Who benefits, how often, severity if wrong.
2. **Strategic fit** — Roadmap themes, compliance, partnerships.
3. **Cost of delay** — Risk if we wait a quarter.
4. **Engineering cost** — T-shirt size is fine; flag DS migrations explicitly.

## Buckets

- **Now** — Committed; protect dates by cutting scope, not quality bar on safety/accessibility.
- **Next** — Defined problem; waiting on capacity or dependency.
- **Later** — Valid idea; intentionally not scheduled.

## Dependencies

- Flag **DS / platform** work that unlocks product features (tokens, shell, navigation).
- Link PRDs and specs in this KB when you add them so RAG can retrieve them.
